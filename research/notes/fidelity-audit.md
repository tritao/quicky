# Faithful-engine fidelity audit

This is the completion matrix for the rendering slice. A row is **measured**
only when a native trace or static code path establishes the behavior. It is
**implemented** only when the engine models that measured behavior and has a
regression test. **Inferred** means the current frontend has a deliberate
policy but the original executable has not yet confirmed it.

## Priority order

1. Wire native lifecycle ownership: delayed player death/checkpoint recovery,
   object teardown/rebuild on reload, and the remaining action transitions.
   These are the largest behavioral differences in the current frontend.
2. Add the measured completion/exit state machine and score-card overlay,
   including the eight cereal increments, bonus branch, input lock, next-level
   routing, and first rebuilt gameplay page.
3. Correlate the settled-menu `0536` upload with the VGA CRTC page handoff and
   capture the remaining selector blink/fixed-label composition. Then add
   title/menu/entry/exit/death golden 320x200 frames.
4. Close the smaller renderer edges: natural per-world LOOP ICO cursor state,
   optional resource fallback, ARE-overlay visibility, and a no-breakpoint PIT
   cadence measurement. Keep the injected BOB `0x0100` branch isolated until a
   natural caller is found.

Until those four priorities are closed, the renderer should be described as
asset-correct and behaviorally instrumented, not a faithful recreation.
